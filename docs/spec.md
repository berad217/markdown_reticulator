# Markdown Reticulator — Spec

## What & Why

A polished single-file HTML app for viewing markdown. Designed for the case where someone wants to send a `.md` file to a non-technical friend or family member and have them be able to read it nicely without installing anything.

**The constraint that shapes everything:** the shareable deliverable is one HTML file. Development happens in a folder; a build step bundles it. This is a hard requirement, not a preference — losing single-file delivery means losing the use case.

## Done criteria for the project as a whole

- Bradley would be happy to email the built file to a non-technical friend.
- Works offline after first open (no CDN dependencies in the built file).
- Safe to open any markdown file, including ones from untrusted sources.
- Feels like a real document viewer, not a developer tool.

## Sprint plan

### Sprint 1 — Foundation + fix broken stuff  ✅ **DONE**

The original `markdown-converter.html` was a single ~790-line file. This sprint splits it into a maintainable layout and fixes the things that are actually broken or risky.

1. **[done]** Restructure `src/`, write `build.py`, verify bundled output matches behavior.
2. **[done]** Vendored `marked.js` v15.0.12 — dropped the CDN dependency.
3. **[done]** Vendored `DOMPurify` 3.4.3 — all rendered HTML sanitized via `markdownToSafeHTML()` before injection. The security fix.
4. **[done]** Fixed: success banner now shows filename + random reference in a single, persistent message.
5. **[done]** Stripped the false "math" claim from the boot console log.
6. **[done]** `spec.md`, `DEVLOG.md`, `README.md`.

### Sprint 2 — Should-haves  ✅ **DONE**

1. **[done]** Paste-text input — collapsible textarea below the drop zone, with a "Render" button and Ctrl/Cmd+Enter shortcut.
2. **[done]** Syntax highlighting via highlight.js 11.9.0 (common bundle).
3. **[done]** Light/dark theme toggle in the header, persisted to localStorage, first-load respects `prefers-color-scheme`. Both highlight.js themes (github light / github-dark) coexist via scoped CSS generated by `scripts/generate-highlight-themes.py`.
4. **[done]** Relative-image notice — info banner appears when a rendered doc contains `<img>` with a relative path.

### Sprint 3 — Nice-to-haves  (3 of 4 done)

1. **[done]** Auto-generated TOC — collapsible `<details>` "On this page", appears only when ≥3 h1/h2/h3 headings. Auto-assigns slug IDs with dedupe.
2. **[done]** Raw/rendered toggle — "View source" button shows the original markdown text in a code block.
3. **[deferred]** Math (KaTeX). The JS would inline cleanly (~280 KB), but KaTeX needs ~200 KB of WOFF2 font files that don't fit the single-file constraint without base64-bloat or a CDN dependency. Math is uncommon in normie markdown, so this gets deferred until we either (a) commit to the size and inline the fonts as data URIs, or (b) accept a CDN dependency just for math.
4. **[done]** Print button — `window.print()` with a print stylesheet that strips the chrome and the TOC.

**Out of scope (decided 2026-05-16):**
- **Mermaid diagrams.** Too heavy (~1 MB) for how rare they are in normie markdown. May revisit later as a lazy-loaded CDN fetch.
- **Automated tests.** UI tool small enough that manual testing per sprint is more honest than green-checkmark theatre. Manual test checklist lives in `docs/DEVLOG.md` per sprint.

**Done when:** opening a real-world markdown doc feels at least as good as viewing it on GitHub. ← We're there for everything except math.

## Folder layout

```
src/
├── index.html          shell, structure, asset links
├── styles/
│   ├── app.css         layout + chrome + print styles
│   ├── rendered.css    rendered markdown styling
│   └── themes.css      light (default) + dark overrides
├── js/
│   ├── references.js   the ridiculous reference table
│   └── app.js          main logic (single file for now — split if it grows)
└── vendor/             third-party libs, vendored for offline use
    ├── marked.min.js              v15.0.12
    ├── dompurify.min.js           3.4.3
    ├── highlight.min.js           11.9.0 common bundle
    ├── highlight-github.css       source for theme combiner
    ├── highlight-github-dark.css  source for theme combiner
    └── highlight-themes.css       generated; both themes scoped by [data-theme]

build.py                            bundles src/ → dist/markdown-reticulator.html
scripts/generate-highlight-themes.py  regenerates highlight-themes.css
dist/                               committed build artifact (~228 KB)
docs/                               spec.md, DEVLOG.md
```

## Non-goals

- Editing markdown. This is a viewer.
- Server-side rendering or hosting.
- Plugin system / extensibility.
- Mobile-first design. Responsive yes, mobile-first no.
- Supporting Internet Explorer or pre-2020 browsers.
